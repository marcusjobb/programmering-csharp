# Testa din kod

Kod som aldrig testas är kod du hoppas fungerar. Kod som testas är kod du vet fungerar.

Det här avsnittet handlar om två kompletterande tekniker: **TDD** (testdriven utveckling) och **kodgranskning**. Ingen av dem garanterar felfri kod. Tillsammans minskar de risken för att problem hittas av användaren snarare än av dig.

## Vad du hittar här

- [TDD](tdd.md) — skriv testet först, implementera sedan. En metod för att tänka igenom vad koden ska göra innan du skriver den.
- [Kodgranskning](kodrecension.md) — hur du förbereder och genomför en pull request-granskning på ett sätt som faktiskt hittar problem.
